# Sprint Plan — 16 × 2-week baseline (32 weeks)
| Sprint | Focus | Exit deliverable |
|---|---|---|
| S1 | SAP landscape and ADT/T-Code R&D | Release/permissions/service inventory and discovery proof |
| S2 | Catalogue and functional R&D | Verified app sample, process and fit-gap model |
| S3 | Generation feasibility | Reference pattern and compatibility report |
| S4 | Architecture sign-off | PRD, ERD, APIs, security, UX and ADRs |
| S5 | BTP foundation | CF deployment, UI shell, CAP, HANA, identity |
| S6 | SAP connectivity | Destination/Connectivity/Cloud Connector proof |
| S7 | Transaction discovery | Real pilot metadata and technical explorer |
| S8 | Business requirements | Process context and confirmed requirements |
| S9 | Fiori catalogue | Search and app details |
| S10 | Fit-gap and decision | Evidence-backed recommendation |
| S11 | Generation specification | App specification and templates |
| S12 | Project generator | One draft project pattern |
| S13 | Validation/governance | Validation centre and approval |
| S14 | Bulk/system scans | Excel and scoped background scans |
| S15 | Hardening | Security, performance, recovery and monitoring |
| S16 | Demo release | End-to-end demo, documentation and readiness review |

The 32-week estimate is a planning baseline, not a commitment. Team capacity, access, entitlements and release complexity can change it.

Sprint Definition of Done: integrated UI/API, persistence, authorization, error handling, tests, logging/audit where applicable, docs, deployment and reviewer acceptance.
